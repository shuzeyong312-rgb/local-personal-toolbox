# 个人工具箱｜批量打水印 UI/UX 重构 PRD V2.0

**对象**：现有 Windows 本地个人工具箱。**任务类型**：在原程序上重构批量打水印页面与少量可复用桌面控件。**优先级**：先修可用性，再改善视觉；不以 Skill 数量作为完成标准。

## 1. 首先校正技术前提

仓库 [`shuzeyong312-rgb/project`](https://github.com/shuzeyong312-rgb/project) 的 `main` 当前使用 **Python + PySide6 + Pillow**。应用入口是 `app/main_window.py`，水印页是 `tools/watermark/page.py`，拖放列表和预览在 `components/`，后台任务在 `tools/watermark/worker.py`，图像处理在 `services/image_processing.py`。README 明确支持单个水印、**平铺水印**、JPG/JPEG/PNG/WEBP、文件夹递归导入、实时预览、批处理和输出重名避让。

上一版 PRD 中的 React/TSX 组件目录、CSS Grid/Flex、`overflow-x`、HTML `input[type=number]` 和浏览器测试方案，不能作为本项目实施指令。本文用 Qt 布局、控件和事件替代。现有 GitHub `main` 与用户截图可能有版本差异；**Codex 实施时先以本机实际分支和代码为准**，记录差异后仍执行以下产品目标。

截图确认的问题：图片区与上传提示重复、右侧设置底部裁切、输入控件被截断、文件操作和预览在窄窗口内相互挤压、底部空进度条占空间。代码额外确认：`QSpinBox` 默认支持滚轮改值；右侧水印和输出为两个 `QGroupBox`；`QSplitter` 两栏和 `PreviewLabel` 最小尺寸共同挤占可用宽度；预览目前先将原图缩小到 900×700，再叠加固定像素水印，可能与实际原尺寸输出的字号和边距效果不一致。

## 2. 产品目标和范围

**目标**：让用户在一个窗口内完成「导入图片 → 选中图片预览 → 调水印 → 确认输出目录 → 批量处理 → 查看结果」。1280×720 及以上的常见桌面窗口内，核心操作始终可达；文字水印的预览能代表实际输出。

**必须保留**：本地处理、选择图片/递归选择文件夹/拖放、单水印与平铺模式、角度和间距设置、当前图片预览、后台处理、单张失败隔离、原图不覆盖、重名自动编号、原有格式与质量策略。批处理服务只修复与本任务有关的实际缺陷，不重写算法。

**本版不做**：迁移 React/Electron/WebView、数据库或插件系统、图片处理流水线重写、图片压缩/改尺寸/格式转换的新工具、动画营销效果、缩略图拖拽排序及任务取消系统。

## 4. 页面布局与滚动

1. 保留目前约 208 px 深色侧栏，仅显示已有工具；不提前制作空白导航、仪表盘或第二级页面。右侧页面头包含「批量打水印」及一句“图片在本机处理；结果另存，不覆盖原图”。去掉多余的重复标题和装饰性眉题。
2. 主工作区左右双栏：左侧弹性伸缩，用于导入、当前大图预览和待处理图片；右侧约 320–340 px，用于统一设置 Inspector。主要视觉焦点是**当前图片和水印位置**，不是按钮或空状态卡片。比例应由 `QHBoxLayout` / 经验证的 `QSplitter`、stretch 和合理 `QSizePolicy` 决定；避免强制给多个大容器设固定宽高。
3. 左侧只保留一个可拖放的图片区域：空时提示“拖入图片或文件夹”，同时提供“添加图片”“添加文件夹”；有图片时显示当前预览、数量、文件名/缩略图选择和“清空”。若本机版本已有列表，应复用或简化，不再叠加第二块虚线上传区。
4. 右侧把水印设置、平铺设置和输出设置放在**一个** `QScrollArea` 中；窗口高度不足时滚动 Inspector，开始按钮始终能通过正常滚动访问，最好固定在 Inspector 底部但不得遮挡内容。图片列表/缩略图可按自身内容滚动；整个工作区不得出现被迫的水平滚动或多层互相争抢的纵向滚动。
5. 状态栏只在处理中显示进度条；空闲显示“就绪”，完成显示“已完成 X 张”及“打开输出目录”，部分失败显示成功/失败数量及可查看失败项。
6. 保持仓库现有窗口最小尺寸 **1080×700** 作为基线。先测试 1080×700、1280×720、1366×768、1440×900、1920×1080；若实测可稳定缩至 1024×680 才下调最小值。另查 Windows 125% / 150% 缩放时标题、按钮和输入值是否裁切。

## 5. 图片导入与预览

- 按钮选多图；文件夹递归扫描支持 JPG/JPEG/PNG/WEBP。拖入图片和文件夹在同一个入口处理。按规范化路径去重；展示“已添加 N 张、跳过重复 M 张、忽略不支持 K 个”，避免静默失败。
- 选择或导入后默认预览第一张。显示当前文件名，长路径用 Qt 的文本省略和 Tooltip 显示完整路径；不要让长路径把右侧挤出窗口。可切换当前图片。清空有图片时二次确认；单张移除属于 P1，若本机已有则保留。
- 文字、字号、透明度、颜色、位置、边距、平铺模式、角度、间距改变后，更新当前图片的预览；保留现有 120 ms 防抖。空文本时给出明确空预览/提示，禁止开始处理。预览只在内存中渲染，不写回原文件。
- **预览和输出的一致性是 P0**：字号、边距、平铺间距当前按原图像素计算，不能先缩小原图再套用同样的数值。优先基于原尺寸生成当前图片结果后再缩放显示；如大图性能/内存不可接受，可在缩放预览时等比例换算字体、边距及平铺参数，并用同一张样图比较最终输出。预览失败不应清空任务，应显示“无法预览此图，仍可尝试批量处理”及原因。
- 导入数百张时文件夹扫描和缩略图生成不能卡住 Qt 主线程；使用现有线程/Qt 信号实现异步扫描、逐步反馈。当前图优先显示，其他缩略图按需生成并缓存有限数量，不把所有原图同时解码。

## 6. Inspector 交互规格

| 控件 | 默认与范围 | 行为及校验 |
| --- | --- | --- |
| 水印文字 | 首次可为空；若启用设置记忆则恢复上次值；1–100 字符 | 用户输入后实时预览；空白或全空格时禁用开始，失焦或提交时提示“请输入水印文字”。不预置某一家公司的名称。 |
| 字号 | 25 px；8–200 px，步长 1 | 共用的 Qt `NumberStepper`：减号、可直接编辑的数字、加号；支持键盘上下键；非法字符拒绝，失焦时裁剪越界值。**滚轮悬停/聚焦都不得改值**。 |
| 透明度 | 50%；10–100%，步长 1% | 滑块旁显示百分比；支持键盘方向键/Home/End。界面百分比转换为当前 `WatermarkOptions.opacity` 所用的 0–255 整数；50% 对应约 128。 |
| 文字颜色 | `#FFFFFF` | 颜色色块调用 `QColorDialog`，旁边支持 `#RGB` / `#RRGGBB` 编辑，统一显示 6 位大写 HEX；无效值保留上次有效值并提示。 |
| 单水印位置 | 默认右下 | **保留当前五个实际可用位置**：左上、右上、居中、左下、右下。可用九宫格外观的五个可选按钮表达位置，其余格不激活；不要仅改 UI 为九个位置却不扩展图像服务。九位置完整支持列 P2，需单独实现并测试服务。 |
| 边距 | 24 px；0–200 px | 复用 `NumberStepper`；滚轮不得改值；仅单水印模式启用。 |
| 平铺模式 | 默认关闭 | 打开后显示/启用现有角度与间距，位置与边距禁用；切回时恢复原位置/边距值。不能从新版 PRD 中消失。 |
| 平铺角度、间距 | 保留现有默认 30°、80 px 和可用范围 | P0 优先保持现有服务合法范围，改用相同的防滚轮数字控件；仅确认数据正确时再缩紧范围。 |
| 输出目录 | 现有默认 `./output`，P1 可记忆最近使用值 | 可编辑路径和选目录按钮；长路径在显示层省略并提供完整 Tooltip，不截断真实路径；不存在则在处理时创建；权限/创建失败显示明确错误。 |

`NumberStepper` 在 Qt 下可用 `QSpinBox.setButtonSymbols(NoButtons)` 加 `−/+` 按钮并在派生类忽略 `wheelEvent`，或用 `QLineEdit` + `QIntValidator` + 按钮实现；由 Codex依据可维护性选一种。必须保留上下键、键盘焦点、范围校验和禁用状态。不能用 Web 的 `::-webkit-inner-spin-button` 或 CSS 事件来解决 Qt 问题。

开始按钮：零图片、无有效文字、输出路径非法或处理中时禁用；有 N 张时文案“开始处理 N 张图片”；处理中显示“处理中 X/N”，避免重复提交。所有会改变任务参数或文件集合的操作在处理中禁用，或明确使用任务开始时的不可变快照并让用户看到当前任务与下一次设置的区别；本版优先前者。

## 7. 任务状态、失败与文件规则

采用清晰的互斥 UI 状态：`idle`、`scanning`、`ready`、`processing`、`completed`、`partial_error`、`failed`。Qt `QThread` 用信号更新 UI；在 UI 线程更新控件。成功/失败数与总数一致；单个文件异常继续处理下一张，失败列表显示文件名和原因，不用一个大模态窗罗列所有结果。

输出仍为新文件：例如 `image.jpg → image_watermarked.jpg`，重名时 `image_watermarked_2.jpg`。输入输出路径相同也不得覆盖原文件；多来源目录下同名图片也须产生不同输出名。图像尺寸、PNG 透明通道以及 JPEG/WEBP 的现有保存策略不能回归。设置持久化可以用 `QSettings`（P1），只保存文字、字号、透明度、颜色、位置、边距、平铺设置和上次输出路径；**不要恢复上次导入的图片任务**。

轻量状态消息可用非阻断的 Qt `QLabel`/状态栏反馈。确认对话框仅用于清空全部等有损操作；“添加成功”“处理完成”无需阻断式弹窗。

## 8. 视觉规范和 Qt 实现约束

- 方向：轻量桌面生产力工具，浅灰蓝背景、白色工作面、深色侧栏、科技蓝作为交互色；减少重复卡片外框和无意义阴影。预览最大面积、设置对齐规整、数据和按钮层级清楚。
- 建议基础色：背景 `#F5F7FA`、表面 `#FFFFFF`、侧栏 `#111827`、主色 `#3478F6`、文字 `#111827`、次级文字 `#667085`、分隔线 `#E4E7EC`、错误 `#D92D20`。使用 `QPalette` / 集中 QSS 常量，不在控件里散落覆盖样式；色值作为设计起点，以 Windows 实际渲染和对比度为准。
- 4 px 间距基准：8/12/16/24 常用；输入与按钮约 40 px 高。标题 24–28 px，区块 16–18 px，正文 13–14 px，辅助 12 px；优先 Windows 常见中文字体。避免把字体或控件设成固定像素高度，导致不同 DPI 下裁切。
- 操作控件有明确 hover、pressed、keyboard focus、disabled 和 processing 状态；通过 Qt `setFocusPolicy`、Label buddy、accessibleName/Description、Tooltip 确保键盘可达。九宫格选择器须支持 Tab 和方向键，选中态不能只靠颜色。
- `QSizePolicy`、layout stretch、`setMinimumSize` 和必要的 `QScrollArea` 控制布局；先找实际 `sizeHint` / minimum width 导致的溢出，再修改。不要以 `setFixedWidth` 堆砌页面，不要用 QSS/截图坐标修补版式。

## 9. 实施顺序与验收

**P0：本轮必须完成**

1. 读取本机项目代码与已安装 Skill 清单；确认截图和仓库 `main` 的差异，列一页简短实施计划与设计意图。
2. 修布局：单一导入区、预览/设置双栏、右侧受控滚动、无裁切和水平滚动；处理原有平铺设置。
3. 做 Qt `NumberStepper`，禁止字号、边距、角度、间距控件的鼠标滚轮改值；字号非法输入与上下限归一。
4. 修预览与输出的一致性；完善文字/路径校验、禁用和进度/部分失败状态。
5. 运行现有 `python -m unittest discover -v`，人工测试 Windows 常见窗口尺寸；为**预览一致性、无覆盖与核心状态**补少量必要测试，避免为纯视觉变化重复写实现镜像测试。

**P1：P0 稳定后同一轮按价值选做**：五位置视觉选择器、轻量缩略图、颜色 HEX 输入、`QSettings` 记忆、长路径省略、文件夹扫描异步化及大量图片性能、清空确认、少量可复用控件和视觉 Token。若时间受限，优先修大批量卡顿与路径可读性，不为了“组件体系完整”拆出十几个空壳类。

**P2：后续独立需求**：真正九位置服务支持、预设模板、批量任务取消、最近目录/历史、其他图片工具。

| 验收场景 | 通过标准 |
| --- | --- |
| 空状态 / 单张 / 20 张拖入 | 一个导入区；数量准确；第一张预览；无重复图片；按钮状态正确。 |
| 文件夹含不支持文件 / 同名文件 | 支持图片被导入，其余给出数量反馈；结果不会覆盖或静默丢失。 |
| 字号 25，悬停和聚焦滚轮；+；输入 999 / 1 / abc | 滚轮保持 25；+ 得 26；失焦归一为 200 / 8；字母不能成为有效值。边距、平铺数值同类验证。 |
| 改透明度 / 位置 / 平铺参数 | 当前预览及时变化；单水印和平铺选项切换正确；导出的水印比例与预览一致。 |
| 1080×700、1280×720、1366×768、1440×900、1920×1080；125%/150% 缩放 | 无水平滚动和控件裁切；右侧能滚到底；CTA 可访问；文件名不挤占布局。 |
| 100–500 张和大图 | 导入有进度/可感知反馈；主窗口仍能响应；没有明显持续内存增长。 |
| 批处理成功 / 部分失败 / 输出路径不可写 | 期间不能重复提交；状态准确；失败可查看原因；可打开已有输出目录；输入文件无改动。 |

**完成定义**：上述 P0 场景通过，现有图像处理测试通过，Windows 截图与四张问题图逐项对照，且修改范围没有扩展到新技术栈或新工具。交付时列出修改文件、改动原因、实际运行测试和未完成的 P1 项。
