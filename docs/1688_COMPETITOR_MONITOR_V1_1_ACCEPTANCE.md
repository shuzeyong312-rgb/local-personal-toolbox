# 1688竞品监控 V1.1 正式验收准备报告

## 1. 验收结论

V1.1 已覆盖 PRD 规定的“竞品库 + 手动采集 + SQLite”范围，并通过服务层、界面层、持久化、异常隔离和真实页面采集检查。当前版本适合进入用户手工验收和真实日常试运行。

本次未开发 V1.2/V1.3，也未增加历史变化检测、自动任务、桌面通知或其他新功能。

## 2. 验收项

| 验收项 | 结果 | 验证证据 |
| --- | --- | --- |
| 单链接添加 | 通过 | 合法链接写入竞品库，首次添加后进入采集；非法域名或路径被拒绝 |

| offer_id 去重 | 通过 | URL 查询参数不同但 offer_id 相同仍返回已有商品，不生成重复记录 |
| 自定义竞品组 | 通过 | 支持新建、重命名、删除和商品移动分组 |
| 自定义名称 | 通过 | 单商品添加或编辑时可保存，重启数据库后仍存在 |

## 3. SQLite 检查

| 检查项 | 结果 |
| --- | --- |
| 重启后数据仍存在 | 通过。测试关闭连接并用同一路径重新建立 `MonitorStore`，竞品名称、备注和快照完整保留 |
| 重复采集形成历史 | 通过。每次成功或部分成功采集均执行 `INSERT`，最新快照按采集时间和 id 读取 |
| 暂停商品不进入批量采集 | 通过。批量入口仅查询 `monitor_enabled=1` 的商品 |
| 修改分组不破坏商品 | 通过。商品仍关联原分组 id，快照不变 |
| 删除分组不破坏商品 | 通过。外键使用 `ON DELETE SET NULL`，商品移动到“未分组”，快照保留 |
| 删除商品 | 符合 PRD。二次确认后通过级联外键删除该商品的快照和事件 |

语义检查结果：

- 多价格按页面顺序保存为列表，界面显示为 `价格1 / 价格2`，未选择最低价或“主价格”。

- SKU 来源仅为当前最终 DOM 中可见的名称。V1.1 不遍历组合，也不声称这是完整 SKU 集合。

## 7. 需要用户手工验证的步骤

以下步骤涉及真实桌面交互、本人登录态和长期使用感受，需要用户在正式数据库上确认：

1. 通过 `run.bat` 启动工具，打开“1688竞品监控”。
2. 确认专用 Chrome 已用 `9222` 调试端口启动、1688 已登录、官方采购助手已启用。
3. 添加一个新商品，填写竞品组、自定义名称和备注；确认首次采集完成后列表与详情数据正确。
4. 一次粘贴 2–3 个不同商品链接；确认全部添加并按顺序采集。
5. 再次添加其中一个带不同查询参数的链接；确认提示“商品已存在”，且没有重复商品。
6. 关闭工具并重新启动；确认商品、分组、名称、备注和最新快照仍存在。
7. 对同一商品执行两次“采集选中”；可通过后续 SQLite 检查或 V1.2 历史界面确认快照数增加，旧数据未覆盖。
8. 暂停一个商品，再执行“立即采集”；确认进度中不出现该商品。恢复后再次执行，确认重新进入队列。
9. 重命名分组，再删除分组；确认商品先显示新分组名称，删除后进入“未分组”，已有快照仍可见。
10. 临时关闭专用 Chrome 后采集一个商品；确认显示明确失败原因。重新启动 Chrome 后可再次成功采集。
11. 临时禁用官方采购助手或使用未出现助手的页面；确认失败原因明确指向官方采购助手。
12. 用 10 个 POC 商品执行一次批量采集，观察进度、取消剩余任务以及单个失败后的继续行为。
13. 连续实际使用 3–7 天，确认 50–200 个商品的串行耗时和页面稳定性可接受。

手工验收应使用真实业务数据库，但不需要清空或修改现有出单日历数据。

## 8. 已知限制

- 依赖本机专用 Chrome、有效的 1688 登录态、CDP 调试端口和官方采购助手。
- 页面或助手 DOM 改版后可能需要维护提取规则。
- V1.1 串行采集；商品较多时耗时与页面加载速度线性增长。
- 当前只读取可见 SKU 名称，不遍历完整组合，不保证全部 SKU、独立价格、库存或真实可售状态。
- 销售与成交数据是页面原始展示值，不代表精确销量或真实日增量。
- V1.1 仅显示最新快照；历史趋势、变化事件中心属于 V1.2，本次未实现。
- 自动运行和桌面通知属于 V1.3，本次未实现。

## 9. 是否建议进入 V1.2

暂不建议立即开始 V1.2。

V1.1 已达到用户手工验收和真实试运行条件。建议先完成上述手工步骤，并用 10 个 POC 商品连续运行 3–7 天。确认登录态、助手加载、批量耗时和字段稳定性没有阻断问题后，再明确批准进入 V1.2。
