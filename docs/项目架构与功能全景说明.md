# 本地个人工具箱：项目架构与功能全景说明

> 用途：让 ChatGPT、Codex 和新开发者脱离历史对话后，仍能准确理解项目并安全修改代码。
>
> 对应状态：2026-09-13 当前工作区。若本文与代码冲突，以代码和测试为准。

## 1. 项目是什么

这是一个面向 Windows 的本地桌面工具箱。当前只提供“图片工具 → 批量打水印”：添加多张图片或整个文件夹，配置文字水印，实时预览，再在后台批量输出。

核心目标：

- 所有图片只在本机处理，不登录、不上传、不访问网络。
- 不覆盖原图；输出重名时自动编号。
- 正式输出不缩放，保留格式和 Pillow 能保留的 EXIF/ICC 信息。
- 单张失败不终止整批任务。
- 自动恢复上次水印参数、输出目录和添加文件目录。
- 最小支持窗口内核心参数一屏可见，避免滚轮误调。

当前不包含账号、数据库、服务端、云同步、图形水印、模板管理、任务历史、断点续传，也没有 macOS/Linux 的正式兼容承诺。

## 5. 启动链路

在项目根目录运行：

```powershell
python main.py
```

调用顺序：

1. `main.py` 调用 `app.main_window.run()`。
2. `run()` 创建 `QApplication`，使用 Fusion 风格并加载 `app.theme.STYLE`。
3. 创建 `MainWindow`，其中创建侧边栏、自定义标题栏和 `WatermarkPage`。
4. `app.exec()` 启动 Qt 事件循环。

`run.bat` 会复用或创建项目内 `.venv`、安装依赖后启动。`start.vbs` 优先用已有虚拟环境隐藏控制台启动；虚拟环境不存在时转调 `run.bat`。

## 6. 窗口与布局

`MainWindow` 的默认尺寸是 `1240 × 820`，最小尺寸是 `1080 × 700`。左侧导航固定 `220 px`，当前 `QStackedWidget` 只有 `WatermarkPage`。

窗口移除了系统标题栏：

- 自定义标题栏负责最小化、最大化/还原、关闭。
- 拖动标题栏调用系统窗口移动；双击切换最大化。
- 窗口边缘 `6 px` 内调用系统缩放，最大化时关闭该逻辑。
- 关闭窗口前调用 `stop_worker()`，等待活动任务安全停止。

水印页面结构：

```text
┌───────────────────────┬──────────────────────┐
│ 图片预览              │ 水印设置             │
│ 空状态 / 当前预览     │ 文字、字号、颜色     │
│ 添加、数量、清空      │ 透明度、位置/平铺    │
│ 已添加图片列表        │ 输出入口、开始处理   │
├───────────────────────┴──────────────────────┤
│ 有任务时：进度、结果、打开输出目录           │
└──────────────────────────────────────────────┘
```

两侧使用 `QSplitter`：左侧最小 `400 px`，右侧最小 `340 px`，伸缩比例约 `3:2`。设置区没有滚动条，核心参数在最小窗口内全部可见。

## 7. 完整用户流程

### 7.1 添加图片

入口有三种：点击“添加图片”、点击“添加文件夹”、拖入图片或文件夹。文件夹会递归扫描子目录。

支持扩展名：`.jpg`、`.jpeg`、`.png`、`.webp`。添加后路径会解析成绝对路径，并按 Windows 习惯不区分大小写去重。第一张图片自动选中；列表显示文件名、大小和移除按钮。

### 7.2 水印参数

| 参数 | 范围/选项 | 页面默认值 |
| --- | --- | --- |
| 水印文字 | 非空自由文字，可选最近记录 | `仅供内部使用` |
| 字体大小 | 8–240 px | 24 px |
| 透明度 | 0–255，界面显示百分比 | 128，约 50% |
| 文字颜色 | Qt 有效颜色 | `#ffffff` |
| 水印位置 | 左上、右上、左下、右下、居中 | 右下 |
| 边距 | 0–1000 px | 24 px |
| 启用平铺 | 开/关 | 关 |
| 平铺角度 | -180°–180° | 30° |
| 平铺间距 | 0–1000 px | 80 px |

单水印显示位置和边距；平铺模式显示角度和间距。切换模式不清除隐藏字段。数字框、下拉框和滑块都忽略鼠标滚轮，但保留点击和键盘调整。

### 7.3 最近三条水印文字

文字框可以直接输入，也可以选择最近真正用于处理的 3 条非空文字。点击输入区时，有历史就自动展开。

- 记录发生在点击“开始处理”时，不是每次编辑时。
- 新使用项放到第一位。
- 重复项去重并移到第一位。
- 依次使用 `A → B → C → B → D`，最终为 `D、B、C`。

### 7.4 实时预览

参数变化会启动 `120 ms` 单次定时器，连续修改只触发最后一次重绘。预览读取当前图片，生成最大 `900 × 700` 的缩略图，再调用正式处理同款 `render_watermark()`。缩略只影响预览，输出始终重新读取原图。

### 7.5 输出目录与开始条件

页面只保留轻量的“输出到：目录名”按钮，tooltip 显示完整路径。默认目录是当前工作目录下的 `output`。

输出校验包括：不能为空、不能是普通文件、已存在目录必须可写；路径尚不存在时，最近的已存在父目录必须可写。合法的新目录会在保存时创建。

开始按钮需同时满足：已有图片、文字非空、输出路径有效、没有任务运行。开始后页面复制图片列表和参数快照，启动工作线程，并锁定所有会改变本次任务输入的控件。

完成后页面显示成功/失败状态，并弹出成功数、失败数、输出目录及最多 10 条失败详情。

## 8. 设置持久化

页面使用用户级 INI 设置：

```python
QSettings(QSettings.Format.IniFormat, QSettings.Scope.UserScope,
          "LocalToolbox", "watermark")
```

具体文件位置由 Qt 和 Windows 用户环境决定，不存入项目目录。

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `version` | int | 配置结构版本，当前为 1 |
| `text` | str | 当前水印文字 |
| `font_size` | int | 字号 |
| `opacity` | int | 透明度 0–255 |
| `color` | str | 颜色 |
| `position` | str | 单水印位置 |
| `margin` | int | 边距 |
| `tiled` | bool | 是否平铺 |
| `angle` | int | 平铺角度 |
| `spacing` | int | 平铺间距 |
| `output_dir` | str | 最近输出目录 |
| `recent_texts` | list[str] | 最近 3 条已使用文字 |
| `source_dir` | str | 最近添加文件/文件夹的目录 |

参数和输出路径即时保存，不需要保存按钮。选择文件时保存第一张图片的父目录；选择文件夹时保存该目录；拖拽时保存第一张图片的父目录。下次文件对话框优先打开 `source_dir`，失效时回退到用户主目录。

读取时会校验类型、数值范围、颜色和位置。损坏值按字段回退，不阻止应用打开。上次输出目录被删除、不可写或磁盘离线时，会回退到 `<当前工作目录>\output` 并提示用户重新选择。

“恢复默认”只重置水印参数，不清空输出目录和最近文字。原则是：

> 记住配置，不记住任务。

所以图片列表、当前预览、进度和结果不会在重启后恢复。

## 9. 图像处理

### 9.1 `WatermarkOptions`

服务层用冻结的 `dataclass` 传递参数：`text`、`font_size`、`opacity`、`color`、`position`、`margin`、`tiled`、`angle`、`spacing`。

注意：服务层字号默认值为 36，页面默认值为 24。UI 总会显式传入页面值；只有直接调用服务默认构造时使用 36。

### 9.2 字体

按顺序查找 `msyh.ttc`、`segoeui.ttf`、`arial.ttf`，最后回退到 Pillow 内置字体。微软雅黑优先保证普通 Windows 的中文显示；缺少候选字体时，内置字体可能无法完整显示中文。

### 9.3 单水印

`render_watermark()` 将源图转为 RGBA，按字体包围盒创建透明文字图层，然后按位置和边距合成。坐标最小为 0，防止水印起点越过上边或左边。空白文字会直接返回 RGBA 图，但正常 UI 会提前禁用开始按钮。

### 9.4 平铺水印

单个文字图层先用双三次采样旋转，再按以下步长覆盖画布：

```text
横向步长 = 旋转后宽度 + 间距
纵向步长 = 旋转后高度 + 间距
```

步长最小为 1。循环从画布外一个水印尺寸开始，到另一侧画布外结束，减少旋转带来的边缘空白。

### 9.5 格式与质量

`process_image()` 完整加载源图，记录尺寸、EXIF 和 ICC，再渲染和保存。

| 扩展名 | 输出 | 策略 |
| --- | --- | --- |
| `.jpg` / `.jpeg` | JPEG | RGB、质量 95、`subsampling=0`（4:4:4） |
| `.webp` | WEBP | 质量 95、`method=6` |
| `.png` | PNG | RGBA、PNG 保存 |

EXIF 和 ICC 存在时传给 Pillow 保存器，实际保留程度取决于格式和 Pillow。保存后若尺寸变化，抛出 `RuntimeError("输出图片尺寸发生变化")`。

正式输出不做缩放、锐化、降噪或颜色增强。JPEG/WEBP 会重新编码，不是字节级无损。

## 10. 输出命名与安全

`output_path()` 依次生成：

```text
photo_watermarked.png
photo_watermarked_2.png
photo_watermarked_3.png
```

候选文件存在就递增，因此不覆盖已有输出和原图。不同目录的同名源图输出到同一目录时会编号，不保留输入目录层级。

## 11. 工作线程和任务状态

`WatermarkWorker(QThread)` 接收图片列表、输出目录和不可变参数快照。

| 信号 | 参数 | 含义 |
| --- | --- | --- |
| `progress` | `done, total, success, failed` | 每张完成后的进度 |
| `completed` | `success, failed, failures` | 整批汇总 |

每张图片单独 `try/except`。失败记录为 `<文件名>: <异常>`，然后继续下一张。线程每轮开始前检查中断请求。关闭窗口时只在图片之间中断，不强杀正在保存的单张图片。

所有批处理页把已有的 `clear_files()` 交给统一 `TaskDialog`。正常完成（允许部分文件失败）后，结果弹窗先保留成功数、失败数、输出目录和失败详情；用户关闭结果弹窗时再清空本次输入。取消、线程异常或其他未完成状态调用 `show_result(..., completed=False)`，因此保留输入供重试。该机制只清理任务输入，不修改页面参数或 `QSettings`。

```text
空状态 ─添加→ 已就绪 ─开始→ 处理中 ─结束→ 已完成
  ▲            │             │
  └──清空──────┘             └──关闭时请求中断
```

## 12. 关键模块参考

- `utils.image_files`：扩展名集合、单文件判断、目录递归排序。只按扩展名筛选，内容有效性由 Pillow 判断。
- `components.controls`：`NoWheelSpinBox`、`NoWheelComboBox`、`NoWheelSlider` 和 `RecentTextComboBox`，统一阻止滚轮误改。
- `PreviewLabel`：空状态、等比预览、拖拽高亮和添加意图信号，不直接修改页面数据。
- `ImageDropList`：接收拖拽并发出路径列表，去重和行创建由页面完成。
- `app.icons`：内嵌 SVG 路径，经 `QSvgRenderer` 绘制为高像素比图标，无外部图标包。
- `app.theme`：集中维护颜色和 QSS；动态属性变化后用 `unpolish/polish` 刷新错误、成功和拖拽状态。
- `utils.system.open_folder`：调用 Windows `os.startfile()` 打开输出目录。

## 15. 错误与边界行为

| 场景 | 当前行为 |
| --- | --- |
| 重复图片 | 静默去重 |
| 不支持扩展名 | 不加入列表 |
| 文件损坏 | 预览报错；批处理记录后继续 |
| 文字为空 | 禁用开始 |
| 输出路径是文件/不可写 | 就地报错并禁用开始 |
| 输出目录不存在 | 父目录可写则允许，处理时创建 |
| 上次输出目录失效 | 回退项目 `output` 并提示 |
| 上次添加目录失效 | 回退用户主目录 |
| 设置损坏或越界 | 单字段回退默认值 |
| 输出重名 | 自动追加 `_2`、`_3` |
| 处理中关闭 | 请求中断并等待线程退出 |

## 16. 已知限制

- Windows 专用点包括 `os.startfile()`、字体路径、BAT/VBS。
- 文件支持先按扩展名判断，没有 MIME 或文件签名校验。
- 不支持 GIF；动画 WebP 没有逐帧语义。
- 没有显式 `ImageOps.exif_transpose()`，带方向标记的特殊图片需样本验证。
- 不保留输入文件夹层级。
- 失败详情只在弹窗展示前 10 条，没有日志文件和失败重试队列。
- 配置写有 `version=1`，但尚无迁移分支；未来改变键语义时需兼容读取。
- 自动化 UI 测试不替代 Windows 100%/125%/150% 缩放人工验收。
